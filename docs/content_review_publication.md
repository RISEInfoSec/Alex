# Content Review publication

A completed authenticated Include decision authorizes publication after all existing checks pass. The owner confirmed this standing authorization on 1 November 2026. No second release approval or minimum batch size is required.

The existing hourly Content Review worker reconciles latest complete D1 submissions and exact content hashes, prioritizes eligible approvals, then prepares an immutable `config/content_review_releases/approved-<unique-id>.json` request on a main-based release branch. Its `release_id` equals the filename stem. Each request uses the schema enforced by `scripts/release_discovery_backlog.py`: authenticated submission receipt; unchanged reviewed-content hash; all six passed content-bound preflight gates; taxonomy evidence; existing publisher target proof; exact source revalidation; and the target row. Only supported research papers use this executor; other formats retain their collection's supported controlled executor.

Run the existing release tests plus `tests/test_approved_publication.py`, open the bounded release PR and merge its checked exact head under the standing authorization. This does not authorize unrelated changes or bypass a required check. The Approved Content Review publication workflow consumes `approved-*.json` requests, rechecks sources/exclusions/duplicates, applies eligible rows additively and writes one durable receipt per request. An individual source failure holds that item while eligible peers proceed. Applied receipts make retries idempotent. A genuinely changed source requires revalidation and a fresh immutable request; never edit an applied request or erase its receipt.

Pages follows successful publication and checks out current main so it receives the corpus commit made during the release. Verify the receipt, successful Pages deployment and the deployed candidate IDs/content hashes before marking work published. A merged request or staged approval is not live publication.

Operational target: next hourly worker pass plus release/deployment, normally within 90 minutes of approval when checks remain passed. On every pass report any eligible approval older than 90 minutes with the actual stalled stage or blocker and continue supported recovery. Preserve approvals, source backoff and all existing quality rules. Notify the owner of failures instead of claiming that a subsequent approval is required.
