# Confirmed private deletion publication

The private Review Site owns flags, reasons, administrator identity and the explicit deletion decision. Flagging is reversible and does not remove a record. The administrator confirms the exact title and publication approval in the Deletion GUI before the Site dispatches `private_deletion.yml` on main.

The Site needs the secret runtime variable `ALEX_GITHUB_TOKEN`: a fine-grained GitHub token restricted to `RISEInfoSec/Alex` with **Actions: read and write**. It does not need Contents write permission. The repository workflow uses its own short-lived `GITHUB_TOKEN` to commit the exclusion and rebuilt corpus. An authoring-session GitHub connection does not supply runtime credentials to a deployed Site. Missing connection configuration disables the delete action with an explanation. Redeploy the saved Site version after adding the secret.

Dispatch inputs contain only an opaque request ID, public bibliographic identity and the hash of the reviewed title/author/year/DOI/source/abstract. Private reasons and Site user IDs never enter GitHub inputs, public receipts or commit messages.

The worker validates that exactly one public record matches, that its reviewed content is unchanged, that canonical/public rows align, and that the exclusion will not affect another record. It removes that canonical row and adds a durable, content-bound entry to `config/corpus_exclusions.json`. Normal publication regenerates JSON, CSV, collections and sitemap. Private deletions are serialized in their own concurrency group so they can start without waiting for a weekly discovery run; a conflicting main push fails visibly instead of overwriting unrelated changes. Deleting the final corpus record requires manual reconciliation because the existing empty-input publisher deliberately preserves its previous public output.

`Pages` runs on successful completion of **Private deletion publication**, including bot-authored commits that do not trigger a downstream push event. The live artifact carries `data/deletion_receipts.json`; only a matching receipt served by the live public site confirms publication. A dispatch acknowledgment or successful source commit is insufficient. The GUI shows pending, failed and published states, retains decision history, and offers an explicit retry. An uncertain dispatch is checked for an existing run before replay; a failed Pages deployment is retried without applying another removal. Repeated worker requests with the same receipt are idempotent.

Recovery is a separate explicit editorial decision through Git history and the exclusion registry; a future discovery or rescore must not undo the removal automatically.

Validation: `python -m unittest discover -s tests -p test_private_deletion_publication.py -v`. The private Site has separate tests for confirmation, administrator checks, concurrent/duplicate submission, stale content, uncertain dispatch, private-data minimization and live-receipt publication tracking. Deployment and hosted GitHub writes must be verified after the runtime credential is configured; fixtures alone do not prove that integration.
